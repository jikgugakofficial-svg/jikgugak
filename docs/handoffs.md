# 직원에게 일 맡길 때 넘기는 쪽지 (매니저용, 2026-10-27~)

참고: every._ai "1인 회사 굴리는 프롬프트 8가지"(10/16). 그 게시물의 핵심은 "다 알아서 해 줘" 한 줄로 맡기지 말고, **직원마다 맡을 일과 넘길 자료를 빈칸으로 정해 두는 것**이에요. 직구각에서 실제로 틀렸던 일(옛 숫자가 글에 남음, 신규 회원가로 판정, 다른 옵션끼리 비교)은 거의 다 "넘긴 자료가 빠졌거나 날짜가 없었던" 경우라서 이 방식을 그대로 가져왔어요.

## 규칙
- 매니저는 직원을 부를 때 아래 쪽지의 `[빈칸]`을 **모두 채워서** 프롬프트 맨 앞에 붙여요. 모르는 칸은 비우지 말고 "없음" 또는 "모름(직원이 찾기)"이라고 적어요.
- 직원은 쪽지에 없는 숫자·날짜를 지어내지 않아요. 빈칸이 일에 꼭 필요하면 추측하지 말고 결과 보고 맨 위에 "빈칸: 무엇"으로 적어요.
- 모든 쪽지 공통 칸: **[기준 날짜·시각] [결과 파일 경로] [하지 말 것]**. 이 셋이 빠진 쪽지는 넘기지 않아요.

## 공통 머리말 (모든 쪽지 맨 앞)
```
오늘: [YYYY-MM-DD HH:MM] / 이번 주 핵심(status.md 0장): [한 줄]
맡길 일: [한 문장, 끝난 상태가 어떤 모습인지]
결과 파일: [경로]   보고 형식: [직원 정의의 보고 형식 그대로 / 바꿀 점]
하지 말 것: [이 일에서 특히 틀리기 쉬운 것 1~3개]
```

## 직원별 쪽지

### price-checker
```
확인할 상품: [슬러그 목록] (최대 [N]개, 쿠팡은 15초 간격)
비교 옵션: [색·용량·축·맛], 쿠팡 itemId: [번호 또는 모름]
알리 기준: 일반가 = 알리 제휴 API 가격 / 아이허브: kr.iherb.com 주소
price-alerts.json에서 처리할 항목: [id 목록 또는 전부]
이 가격이 쓰인 콘텐츠: [content 폴더 또는 없음] → 바뀌면 보고만
```

### product-scout
```
찾을 범위: [품목·브랜드·세일 이름] / 후보 출처: [data/candidates.json 항목 또는 웹]
이미 있는 상품(겹치면 안 됨): data/products.json
등록 가치 3문항(아래) 답을 후보마다 적기
```

### sale-scout
```
확인할 세일: [events.json id 목록 또는 expected 전부]
환율 갱신: [예(월요일) / 아니오]
```

### site-inspector
```
바뀐 곳: [파일·페이지 목록] / 꼭 볼 화면: [주소·폭 360px]
알려진 경고(보고 안 해도 됨): 아이허브 링크 제휴 아님, match 없는 아마존 상품
```

### trend-scout
```
주제: [한 줄] / 연결할 세일: [이름·날짜]
결과 폴더: content/[YYYY-MM-DD-주제]/research.md
특히 찾을 것: [상위 글 제목 패턴 / 사람들이 묻는 질문 / 인기 게시물 훅]
```

### marketing-lead
```
모드: [기획 / 검수]
소재: [한 줄] / 채널: [네이버 / 릴스 / 스레드] (10/31 이후 카드뉴스는 쉼)
쓸 상품: [슬러그 목록], 실물 확인 시각: [YYYY-MM-DD HH:MM 또는 아직]
게시 예정: [날짜·시각] / 5주 계획 번호: [N1·R3 등]
```

### blog-writer · social-writer
```
폴더: content/[폴더] (brief.md 팩트 시트 밖 숫자 금지)
채널·분량: [네이버 1,500~2,500자 / 릴스 20~30초 / 스레드 2개]
CTA: [붙여넣기 판정 / 계산기 장바구니 / 댓글 판정 요청(playbook 참고)]
```

### card-designer
```
폴더: content/[폴더] / 장 수: [N] / 표지 사진: [img/파일 또는 없음]
릴스로도 쓰나: [예·아니오]
```

### cs-responder
```
문의 원문: [붙여 넣기, 개인정보는 가림] / 어디서: [메일·댓글·의견함]
관련 상품: [슬러그 또는 모름] / 답장이 나갈 곳: [메일 / 댓글 답글]
```

## 등록 가치 3문항 (product-scout, 매니저 등록 확인 때도 같이 봄)
참고 게시물의 '아이템 검증 직원'을 직구각에 맞게 바꾼 것이에요. 셋 다 "예"여야 등록 후보예요.
1. **찾는 사람이 있나?** 블로그·커뮤니티·쇼핑 검색에서 "직구"·"알리"·"최저가"와 같이 자주 나오는지(근거 주소 1개).
2. **같은 제품 짝이 되나?** 바코드 또는 모델번호·옵션까지 국내·해외가 같은지(`match` 방법).
3. **판정이 쓸모 있나?** 결과가 직구각이든 국내가 나음이든, 사람들이 헷갈려하는 상품인지(둘 중 하나가 늘 압도적으로 싸면 우선순위 낮춤).
